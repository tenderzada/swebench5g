Why SWE-Bench 5G?

Existing benchmarks (SWE-Bench, SWE-Bench Mobile, BeyondSWE) cover Python, Swift, and general software. None address the telecommunications domain.

Specification-Driven
Correctness is defined by 3GPP Technical Specifications, not just "doesn't crash". Agents must interpret formal protocol text.
Distributed Architecture
Multiple Network Functions run as microservices. A single operation triggers signaling across AMF, SMF, UPF, and more.
Protocol State Machines
5G procedures involve complex multi-step state machines with specific message sequences and error handling paths.

Two Test Strategies

Strategy A: Direct Function Call
Call the buggy function with crash-triggering input. Uses defer/recover to detect panics. Ideal when the function can be called with minimal setup.
Used by: pilot_pcf_879, amf_pr157
Strategy B: Diff-Based Intent Test
Inspired by SWE-Bench Mobile. Read source code and verify fix patterns exist. For functions with complex dependencies that can't be unit-tested.
Used by: amf_pr161, amf_pr118, nssf_pr39

Quick Start

Try the benchmark in minutes.

# 1. Clone the repository git clone git@github.com:tenderzada/swebench5g.git && cd swebench5g # 2. Build the pilot instance cd pilot_pcf_879 && bash scripts/build_image.sh # 3. Validate (3-step check) bash scripts/validate_image.sh Step 1: Existing tests -> PASS Step 2: Fail-to-pass tests -> FAIL (bug confirmed) Step 3: After fix -> ALL PASS # 4. Experience the Agent workflow docker run -it swebench5g/free5gc:pcf_issue_879 cat /opt/task/problem_statement.md /opt/test-suite/run_tests.sh fail # Fix the code, then verify: /opt/test-suite/run_tests.sh all # 5. Load dataset from HuggingFace python -c "from datasets import load_dataset; ds = load_dataset('tenderzada/SWEBench5G')"
